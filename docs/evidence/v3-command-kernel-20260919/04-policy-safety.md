# 04 — Policy and safety

Policy Engine: `app/core/policy_engine.evaluate_command` (COMMAND_POLICY_VERSION 2026-09-19.1), inputs: principal, client, tenant + authorized tenants, roles, scopes, required scope, command type/target/capability, campaign, environment, effect classification, the caller's registered connector authority. Reason codes: scope_missing, wildcard_tenant_prohibited, tenant_not_authorized, client_without_command_authority, target_not_authorized_for_client, command_namespace_not_authorized, campaign_scope_required, operator_role_required, synthetic_command_in_production. Decision evidence (id, version, allow, reason) is persisted in the operation's first audit row. `POST /internal/v1/authorization/check` (#284) remains the thin alias of the same module.

Safety Gate: `app/platform/safety.py` over `config/platform-safety.v1.json` (safety_version 2026-09-19.1): global + provider kill switches (tighten-only at runtime), per-capability gates (classification, Settings effect flags, umbrella controls, allowed environments, campaign scope, synthetic tenant), adapter registered/ready, tenant/global backlog bounds, tenant rate budget. A config switch alone never activates an effect. Denials audited in middleware_control_audit (Postgres) / MemoryDenialAuditSink. Re-evaluated by the worker before execution (`consume_budget=False`).
