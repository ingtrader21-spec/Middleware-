# 05 — Private DB API, raw-SQL surfaces, OpenAPI/Postman authority

## 1. `/internal/v1/database/*` (PAS-102, `bd406a6`)

`app/api/internal/database.py` has prefix `/internal/v1/database` (`:22`). It is registered in
`CANONICAL_ROUTERS` (`app/router_registry.py:42,126-129`) and therefore **mounted on every profile**
(`application.py:157`). The module docstring (`:4-5`) says "integration profile only" (F-11).

**Auth** is `_authorize()` in each handler (`:56-68`):
- The caller is looked up in `CONTROL_PLANE_CALLERS` using the JWT `client_id`
  (`control_plane_auth.py:88-117`).
- The token is then checked with `runtime.tokens.verify(expected_client_id, required_scope)`.
- Scopes are `platform.database.read`, `platform.database.verify` (used only by `/migrations/verify`) and
  `platform.database.admin`, which is **defined but unused** (`:24-26`).
- `RequestGuard` does not cover `/internal/*` (`request_guard.py:190`).

| Method | Path | Scope | SQL / source |
| --- | --- | --- | --- |
| GET | `/health`, `/readiness`, `/status`, `/schema`, `/migrations` | read | snapshot `:88-143`: `current_database()`, `current_user`, `server_version`, `pg_is_in_recovery()`, `to_regclass('public.alembic_version')`, `alembic_version`, `pg_tables`, `pg_stat_ssl WHERE pid = pg_backend_pid()` |
| POST | `/migrations/verify` | verify | same snapshot; `read_only=True` |
| GET | `/pool` | read | asyncpg pool size, idle, min, max (pool P) |
| GET | `/security/tls`, `/security/certificates` | read | `pg_stat_ssl`; `_dsn_policy` (`:71-85`) parses `sslmode`/`sslcert`/`sslkey` from the DSN. `client_certificate_configured` is structurally always false under a locked profile (F-02) |
| GET | `/security/rls` | read | `pg_class.relrowsecurity`, `pg_policies` (`:329-335`) |
| GET | `/performance`, `/locks`, `/capacity` | read | `pg_stat_database`, `pg_locks`, `pg_database_size`, `pg_stat_activity` (`:351-379`) |
| GET | `/backups`, `/backups/latest`, `/restores/latest` | read | whitelisted fields of `backup.json` / `restore.json` in `DATABASE_CERTIFICATION_EVIDENCE_DIR` (`:146-167,389-404`) |

No mutating or raw-SQL route exists. `tests/test_internal_database_api.py:175-185` pins that
`/migrations/apply`, `/sql`, `/query`, `/execute` and `/raw` return 404.
